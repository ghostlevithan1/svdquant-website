svdquant

An adaptive mixed-precision SVD quantizer for transformer language models. It shrinks a model to about 4 to 6 bits per weight, keeps the quality loss measured and visible, and runs it on a consumer NVIDIA GPU, without ever rebuilding the full weight matrix on the decode path.

What it is

A compressor and a runtime, in one package

You point svdquant at a Hugging Face model. It measures the model on calibration text, decides how many bits each layer deserves, and writes a single self-contained folder. That folder holds the weights, the tokenizer and the config, so it runs without the original repository or a network connection.

Sensitivity-based allocation

The bit budget goes where it does the most good. Layers that hurt the output most keep more precision.

Activation-aware low-rank factors

Each layer is split into two small factors, scored by how much it changes the network's real outputs.

Entropy-coded storage

Quantized codes are Huffman-coded where that saves bytes. Metadata stays under 1% of the file.

Fused GPU kernels

Triton kernels dequantize inside the matmul for decoding. PyTorch fallbacks cover machines without Triton.

Quantized embeddings

The embedding table and tied LM head use the same packed codes, so the dense table is never kept in VRAM.

Desktop app

A GUI with a single quality dial for everyday use and an advanced panel for experts.

Roadmap

What it can do today, and where it goes next

Available now

  • Compress Hugging Face Llama, Mistral, Qwen2, Phi-3 and Gemma style models (svdquant compress).
  • Quality dial in the GUI, plus an advanced panel with the full configuration.
  • 4-, 6- and 8-bit group quantization with searched scales and zero points.
  • GPTQ-style error compensation with a safety net that keeps the plain result when compensation does not help.
  • CUDA-graph decode, streaming generation, and a quantized KV cache (fp8 or int8).
  • Quantized embedding and tied LM head, measured at 344 MiB resident for Qwen2.5-0.5B.
  • Exact size accounting, perplexity evaluation, and reproducible reports.

Next goals, in order

  1. Sub-4 bits per weight with perplexity under 21.5Push the average below 4 bits per weight while keeping WikiText-2 perplexity under 21.5 on Qwen2.5-0.5B.
  2. Decode speed at 75% or more of the uncompressed modelOn the same hardware, reach at least 75% of the uncompressed model's tokens per second, with the same generated text.
  3. An easier GUI for beginner and intermediate usersGuided steps, plain-language explanations of the quality dial, and clearer progress and error messages.
  4. Broad RTX supportVerify and support the RTX family, from 30-series (sm_86) onward, with tested kernels and a compatibility report for each card.
