Pipeline deep-dive

From a dense model to a 4 to 6 bit file

svdquant works in two halves. Compression measures the model once and chooses a precision for every layer. Runtime then reads the packed factors directly, so the full weight matrix is never rebuilt when a token is decoded.

Calibrate→Sweep candidates→Allocate bits→Factor and quantize→Store→Decode
1

Calibration: measure what matters

The model runs over a small calibration text once. For each linear layer, the pass records activation statistics that show which input directions the layer actually uses, so errors in important directions count more.

The same calibration pass informs the scale search, error metric and bit allocation, avoiding repeated measurement work.

2

Candidate sweep: try many ways to store each layer

Each layer is tried under a range of factor ranks, bit widths and storage options. Every candidate is scored by its real stored size and measured error. Candidates that are worse on both size and error are dropped because they can never be chosen.

  • Coarse-to-fine search: broad candidates are narrowed before the final comparison.
3

Allocation: spend the bit budget where it helps

Layers are compared by how much their quantization error changes the network's output. A global budget then assigns each layer a candidate so that quality improves fastest per byte. Sensitive layers keep their precision, and tolerant layers give some up.

Some layers are protected: their caps are relaxed and they stay at 8 bits when the budget allows. That protection is why the best measured point (5.77 bits per weight) reaches 13.3 perplexity.

4

Factorization and error compensation

Each weight matrix is split into two low-rank factors, A and B, using a truncated SVD (or a randomized range finder with a seeded projection, so builds are reproducible). Each factor is quantized on its own, and the rank is validated by its residual.

For int4 layers, an error-compensation pass updates the remaining values after rounding. A safety check compares the compensated result with the plain searched quantizer and keeps the better result.

5

Scale search: clipping instead of min and max

Each group's scale and zero point are searched over clipping candidates, weighted by the importance measured during calibration. Local refinement then polishes the best result. This avoids relying on a single min/max range that can hurt quality.

6

Storage: smaller on disk, still fast to load

Quantized codes use compact entropy coding when it saves space without changing quality. The embedding table is stored in a packed form, and the tied LM head shares that storage.

The serialized output includes integrity checks and a verification step that compares predicted size with the actual file.

Runtime: how a token is produced

Decoding and prompt processing want different things, so they use different kernels.

7

Decode: fused dequantize and multiply

For one token, the runtime reads the packed factors and dequantizes them inside the matrix multiply. The full weight is never written out, so VRAM stays low. Computing Y = A (B X) on the factors keeps the arithmetic small.

8

Prefill: dequantize once, then use a dense matrix multiply

Repeating dequantization for every block of tokens is too slow on long prompts. Above 96 activation rows the weight is dequantized once and passed to a dense matrix multiply. On a 2,048-token forward this cut the time from 5,545 ms to 237 ms.

9

CUDA-graph decode

The single-token step is captured once and replayed to reduce launch overhead. Output is token-for-token identical to eager decoding. Sampling and CPU models take the normal path.

10

Quantized KV cache (optional)

Attention states can be stored as fp8-e4m3 codes, or int8 where fp8 is not available, with one fp16 scale per token vector. That roughly halves KV storage. It is turned on per run.

What this page does not claim. Compression is slower than the earlier baseline, mostly in the sweep. Older RTX cards are not yet tested. Sub-4-bit quality is still a goal. See the roadmap for the open items.
